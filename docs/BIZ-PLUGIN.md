# 品类插件化机制

> 目标：一套 SaaS 支撑美容、美发、美甲美睫、皮肤管理、SPA、足浴推拿、中医养生、口腔、体检、轻医美、瑜伽健身等多品类；租户按授权启停，未启用品类全链路拦截。

## 1. 数据模型

### 1.1 平台插件库 `biz_type_plugin`（平台级，白名单）

| 字段 | 说明 |
| --- | --- |
| `biz_type` | 品类编码，如 `BEAUTY` / `DENTAL` |
| `name` / `name_en` | 名称 |
| `icon` | 图标 |
| `medical` | 是否医疗类目（1/0），影响资质提示与合规模板 |
| `default_enabled` | 新租户默认是否启用 |
| `sub_modules` | 可选子模块 JSON（如库存、体检报告、电子病历） |
| `field_template` | 字段模板 JSON（项目/客户/技师扩展字段） |
| `commission_rule` | 默认提成规则 JSON |
| `sort` / `status` | 排序、上下架 |

### 1.2 租户授权 `tenant_biz_type`（租户级）

| 字段 | 说明 |
| --- | --- |
| `tenant_id` | 租户 |
| `biz_type` | 品类 |
| `enabled` | 是否启用 |
| `enabled_at` | 启用时间 |
| `inventory_enabled` | 是否启用库存子模块 |
| `config_json` | 租户级字段模板/参数覆盖 |

### 1.3 业务表 `biz_type`

项目、套餐、预约、订单、会员卡、技师技能、营销活动等均带 `biz_type`，列表按当前租户启用品类过滤；下单/预约/排班/结算时再次校验。

## 2. 启停流程

```
平台超管：新增/编辑插件 → 设置默认开关/医疗标识/字段模板/提成
        │
租户管理员：品类开关页（卡片 + 图标 + 医疗标识）
        │  启用 → tenant_biz_type.enabled=1 + 记录 enabled_at + 审计
        │  停用 → enabled=0 + 隐藏菜单/入口 + 历史数据保留
        ▼
后端 BizTypeGuard：校验租户是否启用该品类
        ▼
前端：菜单/筛选/表单字段动态加载
```

## 3. 全链路拦截

统一校验点（`BizTypeGuard` / Service）：

| 环节 | 行为 |
| --- | --- |
| 项目/套餐列表 | 仅返回启用品类 |
| 新建/编辑项目 | 品类未启用 → 403 |
| 客户预约 | 校验项目/门店品类，未启用 → 403「该品类未开通」 |
| 下单 | 校验订单明细品类，未启用 → 403 |
| 排班/派单 | 技师技能品类未启用 → 不可排班 |
| 结算/提成 | 未启用品类不生成结算 |
| 营销活动 | 仅可选择启用品类 |
| 报表 | 按启用品类维度聚合 |
| 门户/H5/小程序 | 只展示启用品类项目、技师、套餐 |

停用后：

- 历史订单/预约仍可查询、核销、结算（保证履约）；
- 新建入口隐藏；
- 已配置的菜单隐藏；
- 不物理删除数据，重新启用后恢复。

## 4. 平台端操作

路径：平台管理端 → 品类插件

- 卡片列表：图标、名称、医疗标识、默认开关、租户启用数。
- 新增/编辑：编码、名称、英文名、图标、排序、医疗类目、默认开关、子模块、字段模板、默认提成。
- 停用：平台停用后所有租户不可再启用；已启用租户进入只读履约。
- 审计：新增/编辑/停用/默认开关变更全部记录。

## 5. 租户端操作

路径：租户后台 → 品类开关

- 仅展示平台授权/可用的品类；
- 开关实时生效（保存后刷新缓存）；
- 启用后面板展开字段模板与子模块（库存、证书、体检报告等）；
- 保存写审计，记录启停人与时间；
- 停用需二次确认，提示「历史数据保留，新建入口隐藏」。

## 6. 扩展字段模板

`field_template` 示例：

```json
{
  "item": [
    {"key": "skin_test", "label": "皮肤检测", "type": "richtext", "required": false},
    {"key": "instrument", "label": "使用仪器", "type": "select", "options": ["M22", "热玛吉"]}
  ],
  "customer": [
    {"key": "allergy", "label": "过敏史", "type": "textarea"}
  ],
  "technician": [
    {"key": "cert_level", "label": "资质等级", "type": "select", "options": ["初级", "中级", "高级"]}
  ]
}
```

前端按模板渲染；后端存 `ext_json`，不改变主表结构。医疗类目（`medical=1`）额外提示资质与知情同意书。

## 7. 默认提成规则

```json
{
  "defaultRate": 5,
  "tiers": [
    {"min": 0, "max": 10000, "rate": 5},
    {"min": 10000, "max": 30000, "rate": 7},
    {"min": 30000, "max": null, "rate": 10}
  ],
  "byPosition": {"高级技师": 8}
}
```

优先级：项目单独设置 > 技师等级 > 品类默认 > 平台默认。结算时快照规则，后续修改不影响历史结算。

## 8. 初始品类

`data.sql` 已初始化：美容、皮肤管理、美发、SPA、美甲美睫、口腔、轻医美、大健康（可按需扩展足浴推拿、中医养生、体检、瑜伽健身）。医疗类目标识、字段模板、默认提成、子模块均已配置。

## 9. 新增品类步骤

1. 平台端新增插件（编码全局唯一，建议大写英文）。
2. 配置字段模板、子模块、默认提成、医疗标识。
3. 为需要的租户开通（默认开关或手工启用）。
4. 初始化该品类的项目分类、岗位、工位类型字典（全局或租户扩展）。
5. 配置菜单（后台/小程序/H5）。
6. 回归：项目创建 → 预约 → 下单 → 支付 → 核销 → 结算 → 报表。
7. 停用回归：入口隐藏、新建拦截、历史可查。
